# Training objective / API reference

TODOs operate on CPU PyTorch tensors, preserving their gradient graphs. Tensor logits have batch rows and class columns. Targets are integer class IDs, not one-hot arrays. `torch.logsumexp(x,dim=1)` returns one stable log-normalizer per row; `torch.arange(B)` supplies row indices for paired advanced indexing. `.mean()` reduces all entries to a scalar; `.square().sum()` sums squared entries. The exact penalty is lambda times summed squared **weights**, not biases; no division by parameter count or factor 1/2.

The baseline is rate .01, penalty 0; the chosen control changes exactly one setting. `day2.compare_runs(config,objective=callback)` uses the student's four-argument objective in all 24 full-batch SGD updates of both candidates. Supplied setup fixes seed42, checkpoint, 180 training/60 validation/60 reserved-test rows. Returns `(reports,models)` or None when callbacks are unfinished. Config has exactly learning_rate (finite .00001–.1) and penalty (finite 0–.1). Reports have config, curves, validation_loss, validation_accuracy, epochs and seed as specified beside TODO3. Every curve has one float per update; validation_loss is data cross-entropy, not the regularized objective.

The table and optional download describe the **last completed runs**, even when a control changes afterward. The exported factor is derived from those stored configurations; changing controls alone does not retrain or replace the selected model.

`day2.selection_index(index,reports)` validates an index 0/1. `day2.evaluate_reserved(model)` consumes the selected trained model and returns test_n:int, accuracy:float[0,1], image_ids:list[int], protocol:str. Keep this separate Run action until selection; it is not a one-use enforcement lock. Do not tune after test access. A short single-seed comparison does not establish a universal best rate/penalty.
